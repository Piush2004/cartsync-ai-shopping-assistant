# Deploying CartSync AI

This gets the app onto real URLs your tester can reach from her own device
— not localhost. Frontend on Vercel, backend + database on Render, Virtual
Try-On through fal.ai's hosted API. All three require an account signup
that only you can do (I can't create accounts or enter payment details on
your behalf) — everything else is already committed to the repo
(`render.yaml`, `apps/web/vercel.json`, migrations).

Total time: usually well under 30 minutes. Do the steps in this order —
later steps need values produced by earlier ones.

## 1. fal.ai (Virtual Try-On)

1. Go to https://fal.ai and sign up.
2. Go to https://fal.ai/dashboard/keys, click **Create Key**, name it
   anything (e.g. "cartsync-prod"), copy the key immediately — fal only
   shows it once.
3. Keep this key handy for step 2.

Cost: pay-per-use, no subscription. The model used
(`fal-ai/fashn/tryon/v1.6`) is $0.075/generation — a few dollars covers a
lot of testing.

## 2. Render (backend + database)

1. Go to https://render.com and sign up (GitHub sign-in is easiest — it
   also grants repo access for the next step).
2. Push this repo to GitHub if it isn't already there.
3. In the Render dashboard: **New** → **Blueprint**. Select this repo.
   Render reads `render.yaml` from the repo root and shows you a preview:
   one web service (`cartsync-api`) and one Postgres database
   (`cartsync-db`).
4. Click through to create them. Render will prompt you for the env vars
   marked `sync: false` in `render.yaml`:
   - `FAL_API_KEY` — paste the key from step 1.
   - `CORS_ALLOWED_ORIGINS` — leave this blank for now (you don't have the
     Vercel URL yet); you'll come back and set it in step 4.
   - `SECRET_KEY` and `WORKER_API_KEY` are auto-generated by Render — no
     action needed.
5. Wait for the first deploy to finish (it runs `pip install`, then
   `alembic upgrade head` against the fresh Postgres database, then starts
   the server). Note the resulting URL — looks like
   `https://cartsync-api-xxxx.onrender.com`.
6. Confirm it's alive: open `https://cartsync-api-xxxx.onrender.com/api/v1/health`
   in a browser — should show `{"status":"ok"}`.

Free tier note: the web service spins down after ~15 minutes idle and takes
~30-60s to wake up on the next request. Expect the first request after a
lull to be slow — this is normal, not a bug.

## 3. Vercel (frontend)

1. Go to https://vercel.com and sign up (GitHub sign-in again).
2. **Add New** → **Project** → import this repo.
3. Before deploying: click **Edit** next to **Root Directory** and set it
   to `apps/web`. Vercel auto-detects Next.js from there.
4. Add an environment variable: `NEXT_PUBLIC_API_URL` =
   `https://cartsync-api-xxxx.onrender.com/api/v1` (your Render URL from
   step 2.5, **with** the `/api/v1` suffix).
5. Click **Deploy**. Note the resulting URL — looks like
   `https://your-app.vercel.app`.

## 4. Connect them (CORS)

1. Back in the Render dashboard, open `cartsync-api` → **Environment**.
2. Set `CORS_ALLOWED_ORIGINS` to your Vercel URL from step 3.5 (exactly,
   including `https://`, no trailing slash — this is an explicit allowlist,
   not a wildcard, so an exact match matters).
3. Save — Render redeploys the service automatically with the new value.

## 5. Verify

1. Open your Vercel URL, register an account, log in.
2. Walk through: dashboard → measurements/camera (photo-based body
   measurement) → stylist chat → products → try-on (upload a photo of
   yourself + a photo of a garment).
3. If try-on fails with "not configured," double check `FAL_API_KEY` was
   actually saved on Render (step 2.4).
4. If anything 401s or shows a CORS error in the browser console, re-check
   step 4 — the Vercel URL must match `CORS_ALLOWED_ORIGINS` exactly.

## What's intentionally not in this version

- **Avatar / 3D generation** — no UI exists for this yet, out of scope for
  this pass.
- **Local GPU inference for Try-On** — this laptop's GPU can't run it yet
  (CUDA compatibility gap), so Try-On goes through fal.ai's cloud API
  instead. This is why it works from Vercel/Render without your laptop
  needing to be on.
- **Product catalog images** — the demo product catalog
  (`apps/api/services/product_intelligence/catalog_engine.py`) doesn't have
  real images wired in yet; the product grid will look bare. Not a
  functional blocker.
